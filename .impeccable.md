## Design Context

### Users
Three segments using the tool in very different ways:
- **Marco (80%)** — casual pub player, mobile in a noisy bar at night, needs to score faster than a chalkboard. Low tolerance for friction. Uses it for quick match scoring and small pub tournaments.
- **Sandra (club organizer)** — sports club tournament director, primarily on desktop/laptop. Manages group draws, bracket progression, results reporting. Needs reliability above all else (bad venue WiFi).
- **Tobias (league player)** — technical user, developer himself, wants depth: stats, API, streaming overlays. Uses desktop; may also want TV/display mode for venues.

Primary context: **evening/night, semi-dim environments** (bars, sports halls, clubhouses). Glare from overhead lighting is a factor on screens. Often used under mild stress (active game) or social pressure (audience watching the scorer).

Primary device: **Desktop first** — tournament management and bracket overview on laptop. Scoring view can be mobile but the main UI is desktop.

### Brand Personality
**Technisch · Verlässlich · Klar**

The interface is a tool that disappears when you're using it. Like a precision instrument — a chronograph watch, a stadium scoreboard, a referee's clipboard. It communicates exactly what it needs to and nothing more. It earns trust through consistency and accuracy, not decoration.

### Aesthetic Direction
- **Theme**: Dark mode — mandatory for the evening pub/hall context, but NOT casino neon and NOT "hacker RGB." Think professional sports venue scoreboard: constrained palette, high-contrast numbers, purposeful use of colour only for state changes.
- **Colour palette**: Very dark near-neutral surface (not pure black), one primary score-green for wins/active state, one warning-amber for things that need attention. Zero gradient accents.
- **Typography**: Numbers must read at a glance from arm's length. Display font for scores/standings with strong numeral forms. Clean grotesque for UI labels. NOT monospace for everything — JetBrains Mono as the only font is the "developer IDE" reflex, not appropriate for a general-audience product.
- **Density**: High information density is acceptable and expected — this is a sports data tool, not a landing page. BUT density must be structured with clear hierarchy, not a wall of same-size text.

### Anti-references
- **Generic sports app**: blue gradients, rounded cards with emoji icon + heading + text, same card grid repeated endlessly
- **Casino / gambling**: neon on black, gold accents, particle effects, over-animated transitions
- **Excel clone**: gray borders, table-heavy, no visual personality
- **Apple Health / Fitness app**: white, wellness, too much breathing room for a data-dense tool

### Two Completely Separate UI Contexts

**Scorer / Operator UI** — the person running the app:
- A functional tool. Efficiency is the aesthetic.
- Used at arm's length, possibly one-handed, under social pressure (audience watching).
- Dense, fast, compact. Every tap saves time.
- Design goal: invisible — the scorer thinks about darts, not the interface.

**TV / Spectator Display** — what the audience sees:
- A stage, not a tool. Drama is the aesthetic.
- Viewed from 3–5 metres on a large screen (TV, projector).
- Large numbers, strong contrast, high visual impact.
- Can use animation, cinematic framing, dramatic reveals for checkout/bust/winner moments.
- Design goal: memorable — the audience feels the tension of the match.
- **These two views should look and feel completely different.** Shared codebase, separate design language.

### Design Principles
1. **State over decoration** — colour and emphasis serve game state (active player, bust, checkout opportunity). They don't decorate.
2. **Numbers first** — the score remainder is the single most important piece of information. It must dominate the visual hierarchy.
3. **Zero-friction scoring** — the most common action (enter a score) must require minimum taps/clicks and zero cognitive load.
4. **Desktop-primary tournament management** — bracket overview and phase management are the anchor experience on desktop.
5. **TV display is a different product** — full-screen, dramatic, cinematic. Not a scaled-up version of the scorer UI.
6. **No surprises in the scorer view** — reliable, consistent, predictable. A scorer mid-match should never wonder what happened or what to do next.
